## 0. خلاصة دراسة المشروع (Step 0)

### 1. بنية المشروع وهندسة الملفات
- **باني السيرفر والأصول (`site/server/build_worker.py`)**:
  - يقرأ `worker_src.js` ويدمج فيه بيانات الدروس (`lessons.json` + `arabic_lessons_g5_to_g12.json`)، وبنك الأسئلة (`quiz_bank.json`)، وقاموس الصفحات (`PAGES`)، وصفحات واجهة تقني حذيفة (`PAGES_TQ`)، وأداة نور (`tahdir-noor.user.js`)، والأيقونات (`icons.json` + شعارات Base64).
  - يُنشئ حزم أصول مهشّرة (`/d/<hash>/`) لتقسيم البيانات الثقيلة (`study.json`, `games.json`, `finals.json`) لتجنب تضخم حجم `worker.js`.
  - يُخرِج العامل النهائي إلى `site/dist/worker.js`.
- **نواة الخادم (`site/server/worker_src.js`)**:
  - يعمل على Cloudflare Workers مع ربط قاعدة بيانات D1 (`env.DB`) والأصول الثابتة (`env.ASSETS`).
  - يدير المصادقة، وتوجيه المسارات (`/api/*`, `/app`, `/quiz`, `/games`, ...)، وإدارة الجلسات والأجهزة.
- **المكتبة المشتركة للمتصفح (`site/server/common.js`)**:
  - وظائف عامة: `$(id)`, `esc()`, `toast()`, `dialog()`, `api()`, `sidGet()/sidSet()`, `didGet()/didSet()`, `tqUrl()`.
  - معالجة واجهة تقني حذيفة (`/teqany/*`) بتبديل الروابط والأسماء تلقائيًا عبر `MutationObserver`.
- **واجهات العميل (`site/server/client_*.js`)**:
  - صفحات SPA خفيفة تعتمد على Vanilla JavaScript وDOM المباشر مع استهلاك API السيرفر واستخدام متغيرات CSS المشتركة.
- **مسار النشر الآلي (`.github/workflows/deploy-site.yml`)**:
  - يُشغّل `python3 site/server/build_worker.py` ثم يفحص الصياغة `node --check` ثم ينشر إلى Cloudflare عبر `wrangler` عند الدفع إلى فرع `main`.

### 3. بنك الأسئلة والدروس وآلية الحزم (Pack Architecture)
- **حقول بنك الأسئلة (`quiz_bank.json`)**:
  - `qid`: رقم السؤال الفريد
  - `lesson_id`: معرّف الدرس المرتبط في `lessons.json`
  - `type`: نوع السؤال (`mcq` للاختيار من متعدد، وهو المطلوب في الألعاب)
  - `stem`: نص السؤال
  - `choices`: مصفوفة 4 خيارات
  - `correct`: رقم الخيار الصحيح (0-based)
  - `answer`: النص الصريح للإجابة الصحيحة
  - `marks`: درجة السؤال
  - `ao`: هدف التقويم المعرفي (معرفة / تطبيق / استدلال)
  - `difficulty`: الصعوبة (`منخفضة` / `متوسطة` / `مرتفعة`)
  - `outcome`: مخرج التعلم المرتبط
- **ربط الدرس بالمقرر**:
  - `courseKey = (l.subject || '') + '|' + (l.grade || '')`
- **آلية تجزئة الحزم (Data Pack Split)**:
  - الحزم الكبيرة لا تُدمج مباشرة في `worker.js` بل تُحفظ في `site/dist/assets/d/<hash>/<name>.json`.
  - في «ساحة التحدي»، سنقوم بتوليد `arena_pack.json` في `build_worker.py` مقتصراً على أسئلة MCQ الصالحة (مع stem, choices, correct, difficulty, lesson_id, qid)، وتُحمّل عند الحاجة عبر مسار مهشّر أو نقطة API خفيفة تخدم أصول اللعبة، مع إبقاء حجم العامل دون أي زيادة مؤثرة.

## 6. نموذج أمان وتحقق الـ API (API Security & Anti-Cheat Boundaries)

### 1. طبيعة اللعب الفردي ومحدودية حماية جانب العميل (Client-Side Limits)
- في نمط اللعب الفردي، يتم تسليم حزمة الأسئلة والخيارات ومفاتيح التصحيح إلى متصفح العميل لتمكينه من اللعب بسلاسة واستجابة فورية دون الحاجة لإرسال طلب شبكي لكل نقرة إجابة.
- **حدود الحماية:** لا يمكن تقنيًا ادعاء وجود حماية مطلقة ضد الغش (100% Anti-Cheat) في بيئة المتصفح للعب الفردي، حيث يستطيع أي مستخدم خبير فحص الذاكرة أو كود الجافاسكربت المحلي. الحماية المطلقة والتزامن الكامل هما اختصاص نمط الغرف المباشرة المدار بالخادم (المرحلة 3).

### 2. محددات التحقق الصارمة في الخادم (`POST /api/arena/session`)
لمنع التلاعب بالنتائج أو تشويه لوحة المتصدرين وتقارير المعلم:
1. **التحقق من صحة المعرّفات (`qid validation`)**:
   - يتحقق الخادم من وجود كل `qid` مسجل في الجلسة ضمن المقرر المختار، ويرفض أي معرف وهمي أو غريب.
2. **الحد الأدنى لزمن الإجابة (`Minimum Response Time`)**:
   - يُلزم الخادم بأن لا يقل متوسط زمن الإجابة على السؤال الواحد عن 1200ms (1.2 ثانية). الجلسات التي تأتي بأزمنة دون ذلك تُعتبر روبوتات أو نقرات تلقائية وتُرفض أو تُوسم بأنها غير موثوقة.
3. **إعادة حساب النقاط والذهب في الخادم (`Server-Side Recalculation`)**:
   - لا يثق الخادم إطلاقًا بحقل `score` أو `gold` القادم من العميل؛ بل يحسب الخادم النقاط والذهب المستحق من واقع مصفوفة `answers` المرفقة والنمط الملعوب وعدد الإجابات الصحيحة الفعلي.
4. **سقف النقاط والذهب للجولة (`Score & Gold Caps`)**:
   - وضع حد أقصى للذهب المكتسب في جولة واحدة (مثل 200 ذهب) وسقف للنقاط (1,000 نقطة) يمنع أي محاولة لتضخيم الأرصدة عبر تعديل طلب HTTP.
5. **تحديد معدل الطلبات (`Rate Limiting`)**:
   - يُمنع إرسال أكثر من جلسة واحدة كل 15 ثانية للمستخدم الواحد / معرف الجهاز لمنع هجمات الإغراق والتوليد السريع للنقاط.
6. **عزل الاقتصاد عن الدرجات الرسمية**:
   - رصيد الذهب ومشتريات الشخصيات محصورة داخل متجر الساحة الترفيهي، ولا علاقة لها بسجلات الدرجات والتقويم الوزاري.

## القرارات الفنية المسجّلة (Decisions Log)
1. **Decision**: بناء حزمة أصول مستقلة `arena_pack.json` في `build_worker.py` ووضعها ضمن `_PK` في `site/dist/assets/d/<hash>/arena.json` بدلاً من تضمين بنك الأسئلة في نصوص العامل، التزاماً بقيد حجم Worker.
2. **Decision**: اعتماد الاسم البرمجي الداخلي `arena` والاسم الظاهر الموحّد في واجهة الكبسولة «**ساحة التحدي**»، وفي واجهة خبير «**ميدان خبير**» بثابت مستقل.
3. **Decision**: بناء المؤثرات الصوتية برمجياً عبر WebAudio API النقي (مذبذبات Oscillators ونغمات رنين قصيرة) بدون أي ملفات صوتية خارجية لضمان السرعة وملاءمة العمل دون اتصال.
4. **Decision**: إنشاء الرسوم الرمزية للشخصيات بصيغة SVG مدمجة خفيفة ذات طابع تعليمي أصيل (شخصيات مفكر، بطل، مستكشف، عبقري...) وتجنب أي محاكاة لمنتجات تجارية.
5. **Decision**: صياغة قواعد تحقق الـ API للعب الفردي دون ادعاء حماية مطلقة ضد الغش، مع تطبيق التحقق من qid، وأزمنة الإجابة، وإعادة احتساب النقاط بالخادم، والحد الأقصى، ومعدل الطلبات.
6. **Decision (Bundle Size & Asset Offloading)**:
   - تم نقل سكربت الواجهة `client_arena.js` من القالب الداخلي `page()` في `PAGES`/`PAGES_TQ` إلى أصل ثابت مستقل يُخدَم عبر `dist/assets/arena.js`.
   - منع هذا تكرار كود `pack(common + client_arena.js)` المشفر ذي الإنتروبيا العالية في نسختي الكبسولة وتقني حذيفة.
   - النتائج القياسية:
     - حجم `worker.js` في `origin/main`: الخام 22,992,891 بايت، والمضغوط gzip هو 8,610,101 بايت.
     - حجم `worker.js` بعد نقل الأصل: الخام 23,062,794 بايت (+68 KB)، والمضغوط gzip هو 8,616,994 بايت (+6.8 KB فقط، وهو أقل بكثير من حد الـ 50 KB المسموح).
7. **Decision (Stage 3 Live Architecture & DO Hibernation)**:
   - بناء منطق اللعبة الجماعية كوحدة جافاسكربت نقية تماماً `arena_engine.js` خالية من أي اعتماديات خارجية أو `setTimeout`.
   - بناء `ArenaRoom` كغلاف رفيع لـ Durable Objects يعتمد حصرياً على WebSocket Hibernation (`getWebSockets`, `serializeAttachment`) بدون تخزين مقابس في متغيرات الكلاس.
   - الاعتماد على Durable Object Alarms (`ctx.storage.setAlarm`) للمؤقتات، مما يسمح للـ DO بالنوم وتوفير الموارد.
   - فرض سرية الإجابات: لا تُرسل الإجابة الصحيحة أو مفتاح الخيار للعميل أثناء طور السؤال `QUESTION` تحت أي ظرف، وتُكشف فقط في طور النتيجة `REVEAL`.
8. **Decision (Durable Object Security & Token Verification)**:
   - حظر استخراج الدور `role` أو معرّف اللاعب `playerId` من الـ query string.
   - يصدر الخادم رمز مضيف سري `hostToken` عند إنشاء الغرفة (خاص بالمعلمين المسجلين)، ورمز لاعب موقّع `playerToken` عند الانضمام.
   - يتحقق الـ DO من الرموز قبل قبول الاتصال أو تنفيذ أي أمر تحكم أو استعادة جلسة.
   - تنظيف اسم اللاعب من أي وسوم HTML واقتطاعه بحد أقصى 30 حرفاً.
9. **Decision (Strict Teacher Reports & Data Isolation)**:
   - حل تعارض أسماء الأعمدة `ambiguous column name: user_id` في استعلام `top_failed` بإسناد كافة الأعمدة الصريحة إلى `s.user_id`, `s.class_id`, `s.course_key`.
   - ربط جولات الطلاب بكود فصول المعلم النشطة `classes.code` (`class_id`).
   - حصر تقارير المعلم غير المدير على فصوله (`classes.user_id = me.id`) وجولاته التجريبية الشخصية (`s.user_id = me.id`).
   - حذف شرط `course_key IN scope` لمنع أي تسريب لبيانات طلاب مدارس أخرى تدرس نفس المادة.
10. **Decision (Strict Server Answer Verification)**:
    - عدم الوثوق إطلاقاً بحقل `is_correct` المرفوع من العميل في `/api/arena/session`.
    - البحث عن كل `qid` في `ARENA.by_lesson` ومطابقة `chosen_idx === q.correct`.
    - رفض أي سؤال مكرر أو غير موجود برمز خطأ HTTP 400.
    - ربط محفظة الطالب بـ `(class_id, did)` في `arena_student_wallet` مع معاملة ذرية تمنع السحب بالسالب.
11. **Decision (Asset Cache Busting & CSP)**:
    - توليد اسم الأصل المهشّر `arena.<hash>.js` وفق تجزئة محتوى السكربت بخوارزمية SHA-256 مع إتاحة بديل `arena.js`.
    - تحديث ترويسة سياسة أمان المحتوى CSP بالسماح الصريح بـ `connect-src 'self' wss: ws:;`.
    - توثيق اشتراطات iOS Safari: تشفير `wss:` حصرياً عبر HTTPS، إعادة الاتصال التلقائي عند تبديل التطبيقات عبر أحداث `visibilitychange` و`pageshow`، وضرورة تفعيل أصوات WebAudio عبر إيماءة لمس أولية للمستخدم.
12. **Decision (Default Feature Flag)**:
    - ضبط `ARENA_LIVE_ENABLED=false` افتراضياً في `site/wrangler.toml` لترجع كافة نقاط البث الحي رمز 501 حتى موعد الإطلاق الفعلي.
